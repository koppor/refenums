\title{Demonstration of the refenums package}
\date{}
\author{}
\maketitle

\vspace{-12ex}
This document demonstrates the \href{https://ctan.org/pkg/refenums}{refenums} package with the development documents of a reference manager.
The content is a simplified version of \href{https://github.com/JabRef/jabref/tree/main/docs}{JabRef's} requirements, written for \href{https://github.com/itsallcode/openfasttrace}{OpenFastTrace}, and decision records, written in \href{https://adr.github.io/madr/}{MADR}.
Each green box shows the \LaTeX{} code producing the output right above it.

\section{Setup}
\label{sec:setup}

Each kind of item is set up once.
This produces no output.

Features print only their short form (``Feature~1'') and each becomes a subsection:

\bexample
\setupRefEnums[ ][subsection]{Feature}{ONLYSHORT}
\eexample

Risks use no separator (``Risk~1 (R1)''):

\bexample
\setupRefEnums[]{R}{Risk}
\eexample

Requirements use the default separator (``Requirement~1 (Req-1)''):

\bexample
\setupRefEnums{Req}{Requirement}
\eexample

Decision records and the options they consider, too:

\bexample
\setupRefEnums{ADR}{Decision Record}
\setupRefEnums{Opt}{Option}
\eexample

Milestones combine print name and short name (``Milestone~M1''):

\bexample
\setupRefEnums[COMBINED]{M}{Milestone}
\eexample

\section{Features}
\label{sec:features}

\bexample
\defRefEnum{Feature}{Save a library}{save}
The user saves the library to a \texttt{.bib} file.

\defRefEnum{Feature}{Autosave}{autosave}
Every change to the library is saved shortly afterwards, and a backup is kept.
\eexample

\section{Risks}
\label{sec:risks}

\bexample
\defRefEnum{R}{Concurrent modification}{concurrent}
Another process, e.g., a second JabRef instance on a network share, writes the library file while \refEnum{Feature}{save} is running.

\defRefEnum{R}{Incomplete backup}{backup}
A failure while writing a backup during \refEnumFull{Feature}{autosave} replaces a valid backup.
\eexample

\section{Requirements}
\label{sec:requirements}

\bexample
\defRefEnum{Req}{Detect concurrent modification}{detect}
If the library file changed since the save started, the save is aborted with an error.
Mitigates \refEnumFull{R}{concurrent}.

OFT: \verb|req~logic.exporter.concurrent-save-detection~1|, needs: impl, utest
\eexample

\bexample
\defRefEnum{Req}{Keep valid backups}{keep}
A failure while writing a backup leaves the previous backup untouched.
Mitigates \refEnumFull{R}{backup}.

OFT: \verb|req~jabgui.autosaveandbackup.complete-backup~1|, needs: impl, utest
\eexample

\section{Decisions}
\label{sec:decisions}

The optional argument of \verb|\defRefEnum| wraps a single item, here a decision record in a subsection.

\bexample
\defRefEnum[subsection]{ADR}{Replace files atomically}{atomic}

\paragraph{Context and Problem Statement}
How do we write a file so that \refEnumFull{Req}{detect} and \refEnumFull{Req}{keep} hold?

\paragraph{Considered Options}
\begin{itemize}
\item \defRefEnumInline{Opt}{Overwrite in place}{inplace}
\item \defRefEnumInline{Opt}{Write a temporary file and move it over the target}{tmp}
\end{itemize}

\paragraph{Decision Outcome}
Chosen option: \refEnumFullT{Opt}{tmp}, because a failed write leaves the original file untouched and the target can be checked for changes right before the move.
\eexample

\section{Milestones}
\label{sec:milestones}

\bexample
\defRefEnum{M}{Safe saving}{safe}
Reached when \refEnum{Req}{detect} and \refEnum{Req}{keep} are implemented as decided in \refEnum{ADR}{atomic} and covered by unit tests.
\eexample
