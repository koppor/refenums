\vspace{-12ex}
This document demonstrates the \href{https://ctan.org/pkg/refenums}{refenums} package using the project documents of a fictitious lending library app.
Each green box shows the \LaTeX{} code producing the output right above it.

\clearpage

\section{Setup}
\label{sec:setup}

Each kind of item is set up once.
This produces no output.

Phases print only their short form (``Phase~1'') and each becomes a subsection:

\bexample
\setupRefEnums[ ][subsection]{Phase}{ONLYSHORT}
\eexample

Use cases use the default separator (``Use Case~1 (UC-1)''):

\bexample
\setupRefEnums{UC}{Use Case}
\eexample

Risks use no separator (``Risk~1 (R1)''):

\bexample
\setupRefEnums[]{R}{Risk}
\eexample

Decisions are set up like use cases:

\bexample
\setupRefEnums{D}{Decision}
\eexample

Milestones combine print name and short name (``Milestone~M1''):

\bexample
\setupRefEnums[COMBINED]{M}{Milestone}
\eexample

Questions are used inline, see \cref{sec:questions}:

\bexample
\setupRefEnums{Q}{Question}
\eexample

\section{Lifecycle}
\label{sec:lifecycle}

\bexample
\defRefEnum{Phase}{Analysis}{analysis}
We collect the use cases (\cref{sec:usecases}) and assess the risks (\cref{sec:risks}).

\defRefEnum{Phase}{Design}{design}
We record the architecture decisions (\cref{sec:decisions}).

\defRefEnum{Phase}{Implementation}{impl}
We build and test the app.
\eexample

\section{Use Cases}
\label{sec:usecases}

\bexample
\defRefEnum{UC}{Borrow a book}{borrow}
A member borrows an available book for four weeks.

\defRefEnum{UC}{Return a book}{return}
A member returns a book, which becomes available again.
\eexample

\section{Risks}
\label{sec:risks}

\bexample
\defRefEnum{R}{Loss of lending records}{loss}
Without the records, \refEnumFull{UC}{return} cannot tell who has a book.

\defRefEnum{R}{Double booking}{double}
Two members could borrow the same copy at once (\refEnum{UC}{borrow}).
\eexample

\section{Decisions}
\label{sec:decisions}

The optional argument of \verb|\defRefEnum| wraps a single item, here in a subsection.

\bexample
\defRefEnum[subsection]{D}{Store lending records in a transactional database}{db}
This mitigates \refEnumFull{R}{loss} and \refEnumFull{R}{double}.
\eexample

\section{Milestones}
\label{sec:milestones}

\bexample
\defRefEnum{M}{Specification approved}{spec}
Ends \refEnumFullT{Phase}{analysis}.

\defRefEnum{M}{First release}{release}
Ends \refEnum{Phase}{impl} and delivers \refEnum{UC}{borrow} and \refEnum{UC}{return}.
\eexample

\section{Open Questions}
\label{sec:questions}

\bexample
\defRefEnumInline{Q}{Reservations}{reserve} Can members reserve a borrowed book?
\defRefEnumInline{Q}{Fees}{fees} Are late returns charged?
\eexample

\section{References}
\label{sec:references}

Each kind of reference to \refEnum{UC}{borrow}:

\bexample
\begin{itemize}
\item \verb|\refEnum|: \refEnum{UC}{borrow}
\item \verb|\refEnumFull|: \refEnumFull{UC}{borrow}
\item \verb|\refEnumFullT|: \refEnumFullT{UC}{borrow}
\item \verb|\nameref|: \nameref{enum:UC:borrow}
\item \verb|\ref|: \ref{enum:UC:borrow}
\end{itemize}
\eexample

A traceability sentence combining them:

\bexample
\refEnum{M}{release} is reached once \refEnumFull{D}{db} is implemented; \refEnumFull{Q}{reserve} is still open.
\eexample
