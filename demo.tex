\title{Demonstration of the \texttt{refenums} package}
\date{}
\author{}
\maketitle

\vspace{-12ex}
This document demonstrates the \href{https://ctan.org/pkg/refenums}{\texttt{refenums}} package with the development documents of a reference manager.
The content is a simplified version of \href{https://github.com/JabRef/jabref/tree/main/docs}{JabRef's} requirements and decision records, written in \href{https://adr.github.io/madr/}{MADR}.

Each section starts with an orange box setting up a kind of item; this produces no output.
Each green box shows the \LaTeX{} code producing the output right above it.
Items are defined with shorthands such as \verb|\defReq| and \verb|\defReqInline|, which \verb|\setupRefEnum{Req}| creates for \verb|\defRefEnum{Req}| and \verb|\defRefEnumInline{Req}|.

\section{Features}
\label{sec:features}

\bsetup{Features print only their short form (e.g., ``Feature~1'') and each becomes a subsection.}
\setupRefEnum[separator={ }, enclosing=subsection]{Feature}{ONLYSHORT}
% With the default separator "-", this would print "Feature-1"
\esetup

\bexample
\defFeature{Save a library}{save}
As a researcher, I want to save my library to a \texttt{.bib} file, so that I can cite its entries in \LaTeX{}.
\eexample

\bexample
\defFeature{Autosave}{autosave}
As a researcher, I want every change to be saved automatically and a backup to be kept, so that I do not lose work after a crash.
\eexample

\section{Risks}
\label{sec:risks}

\bsetup{Risks use no separator (e.g., ``Risk~1 (R1)'').}
\setupRefEnum[separator={}]{R}{Risk}
% With the default separator "-", this would print "R-1"
\esetup

\bexample
\defR{Concurrent modification}{concurrent}
Another process, e.g., a second JabRef instance on a network share, writes the library file while \refEnum{Feature}{save} is running.
\eexample

\bexample
\defR{Incomplete backup}{backup}
A failure while writing a backup during \refEnumFull{Feature}{autosave} replaces a valid backup.
\eexample

\section{Requirements}
\label{sec:requirements}

\bsetup{Requirements use the default separator (e.g., ``Requirement~1 (Req-1)'').}
\setupRefEnum{Req}{Requirement}
% Titles are set in italics; titleformat={} would set them upright
\esetup

\bexample
\defReq{Detect concurrent modification}{detect}
If the library file changed since the save started, the save is aborted with an error.
Mitigates \refEnumFull{R}{concurrent}.
\eexample

\bexample
\defReq{Keep valid backups}{keep}
A failure while writing a backup leaves the previous backup untouched.
Mitigates \refEnumFull{R}{backup}.
\eexample

\section{Decisions}
\label{sec:decisions}

\bsetup{Each decision record becomes a subsection. Decision records and the options they consider use the default separator.}
\setupRefEnum[enclosing=subsection]{ADR}{Decision Record}
\setupRefEnum{Opt}{Option}
\esetup

\bexample
\defADR{Replace files atomically}{atomic}

\paragraph{Context and Problem Statement}
How do we write a file so that \refEnumFull{Req}{detect} and \refEnumFull{Req}{keep} hold?

\paragraph{Considered Options}
\begin{itemize}
\item \defOptInline{Overwrite in place}{inplace}
\item \defOptInline{Write a temporary file and move it over the target}{tmp}
\end{itemize}

\paragraph{Decision Outcome}
Chosen option: \refEnumFullColon{Opt}{tmp}, because a failed write leaves the original file untouched and the target can be checked for changes right before the move.
\eexample

\section{Milestones}
\label{sec:milestones}

\bsetup{Milestones combine print name and short name (e.g., ``Milestone~M1'').}
\setupRefEnum[combined]{M}{Milestone}
% Without combined, this would print "Milestone 1 (M-1)"
\esetup

\bexample
\defM{Safe saving}{safe}
Reached when \refEnum{Req}{detect} and \refEnum{Req}{keep} are implemented as decided in \refEnum{ADR}{atomic} and covered by unit tests.
This mitigates \zcref{enum:R:concurrent,enum:R:backup}.
\eexample

\section{References}
\label{sec:references}

The package \texttt{refenums} offers several ways to reference an item.
They differ in how much of the item they show: its kind, its identifier, its title, or a combination.
The following table shows each of them for \refEnum{Req}{keep} from \zcref{sec:requirements}.

\begin{center}
\small
\renewcommand{\arraystretch}{1.3}
\setlength{\tabcolsep}{4pt}
\begin{tabular}{@{}l>{\footnotesize}ll@{}}
\toprule
Aim & Command & Output \\
\midrule
Identifier & \verb|\refEnum{Req}{keep}| & \refEnum{Req}{keep} \\
Identifier (title) & \verb|\refEnumFull{Req}{keep}| & \refEnumFull{Req}{keep} \\
Identifier: title & \verb|\refEnumFullColon{Req}{keep}| & \refEnumFullColon{Req}{keep} \\
Title & \verb|\refEnumTitle{Req}{keep}| & \refEnumTitle{Req}{keep} \\
\midrule
\multicolumn{3}{@{}l}{\emph{With the kind of the item}} \\
Identifier & \verb|\refEnum*{Req}{keep}| & \refEnum*{Req}{keep} \\
Identifier (title) & \verb|\refEnumFull*{Req}{keep}| & \refEnumFull*{Req}{keep} \\
Identifier: title & \verb|\refEnumFullColon*{Req}{keep}| & \refEnumFullColon*{Req}{keep} \\
\bottomrule
\end{tabular}
\end{center}

\verb|\refEnum*{Req}{keep}| is short for \verb|\zcref{enum:Req:keep}| of \href{https://ctan.org/pkg/zref-clever}{zref-clever}, which also references several items at once, as in \zcref{sec:milestones}.

The following list references every item of this document in the form ``Identifier (title)''.

\bexample
\begin{itemize}
\item Features: \refEnumFull{Feature}{save}, \refEnumFull{Feature}{autosave}
\item Risks: \refEnumFull{R}{concurrent}, \refEnumFull{R}{backup}
\item Requirements: \refEnumFull{Req}{detect}, \refEnumFull{Req}{keep}
\item Decision records: \refEnumFull{ADR}{atomic}
\item Options: \refEnumFull{Opt}{inplace}, \refEnumFull{Opt}{tmp}
\item Milestones: \refEnumFull{M}{safe}
\end{itemize}
\eexample
